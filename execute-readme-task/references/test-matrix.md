# 组合测试矩阵

不要只为每个端点写一个成功用例。将测试设计为需求、不变量、状态转换和规则组合的证据网。

## 建立可追溯矩阵

| 用例 ID | 覆盖需求 | 覆盖不变量 | 前置状态 | 操作 | 预期输出 | 预期副作用/不变集 |
|---|---|---|---|---|---|---|
| T1 | R1 | I1,I3 | 具体实体和时间 | 具体请求 | 状态码与 JSON | 存储、计数器、审计、幂等记录 |

每个必须需求至少有一个正向和一个失败/边界证据。每个重要不变量至少被一个直接断言覆盖，不要只通过“请求未报错”间接推断。

## 生成基础契约用例

对每个输入字段覆盖：

- 缺失、`null`、错误 JSON 类型、空字符串/纯空白和非法枚举；
- 整数与 JSON boolean 的区分，数值的下界、上界及界外值；
- 主键、组合唯一键、独立唯一键和不存在的引用；
- 错误码、错误响应结构和非空说明；
- 列表的精确过滤、字符串 ID 排序、数组去重排序和可空字段。

## 生成状态与历史用例

对每个状态转换覆盖：合法转换、非法前置状态、重复操作、终态再操作、不对称分支和转换后查询视图。

对时间/历史覆盖：

- `start-1`、`start`、区间中部、`end-1`、`end` 和超界时刻；
- 业务发生时间与记录时间不同的迟到事件；
- 一次时钟推进跨越多个截止点，各自事件使用真实截止时间；
- 同一时刻旧区间结束与新区间开始的归属。

## 生成原子性、幂等和并发用例

对每个写操作记录请求前的全部受影响状态，让失败用例断言：

```text
实体 + ID 计数器 + 历史 + 审计 + 幂等记录
在失败请求前后完全一致
```

幂等必测：首次成功、完全相同重放、方法变化、路径变化、请求体变化，以及首次响应在后续状态变化后仍保持原快照。

并发必测：重复唯一创建、并发消费同一个一次性资源、同一预期版本决议、同一修订/代次更新和审计序号连续性。期望结果必须符合某一串行顺序，不得两个冲突操作都成功。

## 生成跨规则组合用例

不要穷举全组合；使用风险导向的成对组合，优先以下交叉：

| 规则 A | 规则 B | 必须验证的结果 |
|---|---|---|
| 多原因限制 | 解除一条 | 其他原因仍生效，不提前恢复 |
| 修订/代次变化 | 旧授权 | 钉住值过时，旧授权不生效 |
| 暂停 | 到期/撤销 | 解除暂停后不复活终态资源 |
| 历史事件 | 当前状态已变 | 按历史区间判断，同时保留当前记录时间 |
| 失败校验 | 已分配资源 | 实体、计数器、审计和幂等记录均回滚 |
| 不对称决议 | 多个分支 | 可信分支、非可信分支和原身份分别处理 |

对每个跨实体业务事件，在操作后同时查询所有受影响实体和派生能力，不要只断言主响应。

## 执行测试门禁

- [ ] 所有必须需求和核心不变量均可追溯到用例。
- [ ] 输入契约已覆盖类型、边界、空值、唯一性和引用。
- [ ] 所有状态转换均有成功与非法前置用例。
- [ ] 时间包含/排除边界和迟到事件已覆盖。
- [ ] 失败请求断言完整状态不变，包含计数器和审计。
- [ ] 幂等快照、冲突重放和关键并发冲突已覆盖。
- [ ] 每个高风险规则至少与一个其他规则组合验证。

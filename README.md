# README Task Executor

一个面向能力较弱编码模型的低自由度 Skill：读取项目 README，将综合任务拆成可验证的小步骤，逐步实现，并用实际执行结果完成验收。

## 为什么这样设计

弱模型处理综合任务时，常见问题是遗漏要求、过早写代码、同时修改过多内容，以及没有运行测试就声称完成。这个 Skill 使用固定状态机约束执行顺序：

```text
发现事实 → 建立需求矩阵 → 分析差距 → 原子化计划
    → 单步实现 → 局部验证 → 整体验收 → 证据报告
```

关键约束包括：

- 区分明确需求、推断和未知项。
- 每个计划步骤只处理一个可观察目标。
- 当前步骤验证通过后才能进入下一步。
- 同一失败连续修复两次后，强制重新分析根因。
- 没有实际运行的验证证据，不得标记完成。
- 保护仓库中与任务无关的用户改动。

## 目录结构

```text
execute-readme-task/
├── SKILL.md
└── agents/
    └── openai.yaml
```

## 安装

将 `execute-readme-task` 目录复制到 Codex Skills 目录：

```bash
cp -R execute-readme-task "${CODEX_HOME:-$HOME/.codex}/skills/"
```

## 使用

在包含 README 的项目中调用：

```text
使用 $execute-readme-task，根据 README 完成当前项目，并逐项给出验收证据。
```

也可以附加具体目标：

```text
使用 $execute-readme-task，实现 README 中“批量导入”和“错误恢复”两部分。
不要修改公开 API；运行项目推荐的测试，并报告未验证项。
```

## 对 README 的建议

为了减少模型猜测，README 最好明确提供：

- 最终可观察目标；
- 必须完成和不在范围内的事项；
- 输入、输出与接口约束；
- 依赖、构建、运行和测试命令；
- 可逐项检查的验收标准。

当 README 信息不足且会影响公开接口、数据、安全、成本或破坏性操作时，Skill 会停止执行并请求用户决策。
